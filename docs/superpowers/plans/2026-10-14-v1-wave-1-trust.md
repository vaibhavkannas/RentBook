# RentBook v1 wave 1: trust (correctness, resilience, security)

> For agentic workers: implement task by task, test-first, with the verification gates below. Steps use checkbox syntax.

**Goal:** Remove the correctness, resilience and security defects found by the 2026-10-14 audits, with no visible product change except error pages and clearer messages. The owner's live behaviour and data must not change.

**Roadmap:** `docs/product/ROADMAP-v1.md` (wave 1). **Tech:** Next.js 16.3.8, React 19, TypeScript strict, Vitest, zod, `@googleapis/sheets`, `next-auth@5.0.0-beta.32`.

## Global constraints

- This is not the Next.js you know (`AGENTS.md`): before using any Next API (proxy, headers, route config, `instrumentation`, `cookies`, `connection`) read the matching doc under `node_modules/next/dist/docs/`. In this version the former `middleware` file is `src/proxy.ts` and exports `proxy`.
- Writes stay RAW. No real email address anywhere in the repo (example.com only). Never read, print or commit secrets. Never run `npm run verify:testcopy` (the lead runs it). Never push. Work on the branch named in your instructions.
- Every commit message ends with a blank line and `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- Keep all existing tests green; update a test only when behaviour intentionally changes, and say why. `npm test`, `npm run typecheck`, `npm run lint` and `npm run build` pass at the end of every task (retry the build with `NODE_OPTIONS=--use-system-ca` if it fails fetching Google Fonts with a certificate error).
- Plain-English user-facing messages. Technical detail goes to server logs.
- The in-memory `FakeGateway` (`tests/support/fake-gateway.ts`) must be made to behave like Google where the audits showed it differs (see 1A-3).

## Part 1A: data layer (branch `v1-wave-1a`)

### 1A-1 Month cells parsed one by one (audit D1, D8.1)

Files: `src/lib/sheets/schedule.ts`, `src/lib/domain/month-codec.ts`, `src/lib/domain/year-month.ts`, tests.
- Today one codec is detected from the bottom-most readable Month cell and used to read every row; rows in another format or with an unknown name are silently dropped. Change reading to parse EACH Month cell independently: a number is a Google date serial (accept only years 2000 to 2100; otherwise unreadable), a string is a text month. Text months: English month names and prefixes of at least 3 letters with optional trailing `.` ("Sep", "Sept", "sept.", "September"), followed by a separator (`-`, space, `/`, `'`) and a 2- or 4-digit year; also ISO `YYYY-MM`. Keep the bottom-most-cell codec ONLY for WRITING a new month row in the same style the sheet already uses.
- A non-empty Month cell that cannot be read is a `sheetStructure` error naming the row number and the cell text (cut to 40 characters), but ONLY when it sits above a later readable month row (inside the table). Unreadable cells below the last readable month row (footer labels such as "Total") stay ignored as today.
- Tests: mixed date and text rows, "Sept-26", a garbled cell inside the table (error names the row), a footer label (ignored), a stray number such as 5 in a date sheet (error, not a "1900-01" row), serials outside 2000 to 2100.

### 1A-2 Messages for month ordering (audit D8.2)

File: `src/lib/sheets/service.ts` (`ensureMonthRow`). When the requested month has no row and is not exactly the month after the last row, use `formatMonthTitle` ("January 2027") instead of ISO keys, and say what to do: either "Add the row for <month> in your Sheet" or "Log <next month> first". Update the tests that pin the old text.

### 1A-3 Safer concurrent writes (audit D2, D12 partly)

Files: `src/lib/sheets/service.ts`, a new `src/lib/sheets/write-lock.ts`, `tests/support/fake-gateway.ts`, new tests.
- Add an in-process async mutex (`withWriteLock(fn)`, FIFO, releases on throw) and run `logPayment`, `undoPayment`, `saveTenancy` and `moveOutTenancy` inside it (these already invalidate the cache in `finally`).
- In `ensureMonthRow`, re-read the target row immediately before the clone and refuse (conflict) if it is no longer empty.
- After `updateValues` in `logPayment` and `undoPayment`, read the written cells back (`getValues`, UNFORMATTED_VALUE) and throw a `conflict("Your change may not have been saved. Refresh and check this month.")` when they differ from what was written. Keep the read-back to ONE call.
- Make `FakeGateway.cloneRow` behave like Google: it OVERWRITES the target row (no refusal when the target has content). Add a latency option (`delayMs` per call) and a test that two concurrent `logPayment` calls for different portions in a brand-new month, started 1 ms apart, both end up in the Schedule (the mutex serialises them).
- Update the comment in `src/lib/sheets/gateway.ts` about `cloneRow` to say what is and is not atomic.

### 1A-4 Tabs removed or renamed at runtime; first-run seeding (audit D3, D7, F15)

Files: `src/lib/sheets/settings-store.ts`, `src/lib/sheets/google-gateway.ts`, `src/lib/sheets/google-errors.ts`, tests.
- Map a Google 400 whose message matches `Unable to parse range` (or `Requested entity was not found` for a tab) to a `sheetStructure` error: `The tab "<name>" was not found in your Sheet. Restore it from File > Version history or rename it back.` (the gateway knows the tab it was asked for). On that error also clear the per-gateway bootstrap marker (`bootstrapped` WeakSet: export a `resetBootstrap(gateway)` helper) so the next request re-checks the tabs.
- First-run seeding: if the `Settings` tab is MISSING but `Payments Log` or `Tenants` already exists, do NOT recreate Settings; throw a `sheetStructure` error: "The Settings tab is missing. Restore it from File > Version history or rename it back. RentBook will not recreate it because that would reset your rent cycle lengths and hike percentages." If none of the three app tabs exist (a fresh Sheet) seed as today. If `Settings` exists but has no portion rows (empty or header only) seed it from the Schedule header.
- When `addTab` fails because the tab already exists (two instances starting together), re-list the tabs and continue instead of failing.
- Tests for each rule with `FakeGateway`.

### 1A-5 Hand-edit hazards in Settings (audit D8.3)

Ignore rows whose Tenant, Count and Amount header cells (columns C to E) are all blank (a note typed under the table); if only some of them are filled, throw a `sheetStructure` error naming the Settings row. Only accept ids matching `^[A-Za-z0-9_-]{1,20}$`. Use `Map` (or `Object.create(null)`) for records keyed by portion id in `schedule.ts` (`portionCols`, `entries`) and in the domain types that carry them; fix usages. Tests include an id of `__proto__`.

### 1A-6 One Google read per snapshot, quota and retry (audit D4, D5, F14)

Files: `src/lib/sheets/gateway.ts`, `google-gateway.ts`, `service.ts`, `settings-store.ts`, `tenants-store.ts`, `tests/support/fake-gateway.ts`, tests.
- Add `getManyValues(requests: {tab: string; a1: string}[], render: ValueRender): Promise<unknown[][][]>` to `SheetsGateway`, implemented with `spreadsheets.values.batchGet` (one HTTP call), the fake accordingly. Refactor `readSettingsRows` and `readTenancies` into pure parse functions over raw values (keep the old async functions as thin wrappers so other callers still work). `loadSnapshot` then makes ONE `getManyValues` call (Settings `A1:G50`, Schedule `A1:ZZ`, Tenants `A1:P`) after the tab bootstrap. Keep the Tenants header validation per read and its graceful degradation. Test: a snapshot costs exactly one `getManyValues` call and no other reads (assert with the fake's call log).
- Cache the spreadsheet `sheetId`s and row counts per `GoogleSheetsGateway` instance (used by `cloneRow` and `appendDimension`); clear them when a tab error is seen.
- `createSheets({ version: "v4", auth, timeout: 10_000 })`. Reads retry up to 2 times with exponential backoff and jitter on 429 and 5xx (explicit `retryConfig`, not library defaults). `values.batchUpdate` (idempotent) may retry the same way. `values.append` and structural `batchUpdate` calls are NEVER retried. Each route handler and each page that reads the Sheet exports `maxDuration = 15`.
- `src/lib/errors.ts`: add codes `rate-limited` and `unavailable`. `src/lib/server/http.ts`: HTTP 429 with `Retry-After: 30` for rate-limited, 503 for unavailable. `src/lib/sheets/google-errors.ts`: 429 maps to `rate-limited` ("Google is limiting requests right now. Wait a minute and try again."), 5xx and network errors (`ECONNRESET`, `ETIMEDOUT`, `ENOTFOUND`, fetch failures) to `unavailable` ("Google isn't responding. Try again in a minute."), 401 / `invalid_grant` / `invalid_client` to a config error ("Google rejected the service account key. Create a new key and update GOOGLE_SERVICE_ACCOUNT_JSON."). 403 and 404 keep their current messages. The detailed config text is shown only to the owner; members see "The Sheet connection needs attention. Ask the owner." (apply in the pages and `handle()` using the viewer, log the detail server-side). Update tests; add tests for each mapping and for retry counts (use fake timers or a zero-delay option).

## Part 1B: server and security (branch `v1-wave-1b`, built on 1A after it is merged)

### 1B-1 Log retry without forgery or duplicates (audit F1, D6)

Files: `src/app/api/payments/log-retry/route.ts`, `src/app/api/payments/route.ts`, `src/app/api/payments/undo/route.ts`, `src/lib/server/schemas.ts`, a new `src/lib/server/retry-token.ts`, `src/lib/sheets/service.ts` (`retryLogRow`, `appendLogRow`), `src/components/PaymentSheet.tsx`, `UndoSheet.tsx`, tests.
- `/api/payments` and `/api/payments/undo` return `retryToken` (only when `logWritten` is false) instead of the raw row. Token = `base64url(JSON{row, viewer, iat})` + `.` + `base64url(HMAC-SHA256(AUTH_SECRET, "log-retry:" + payload))`. `/api/payments/log-retry` accepts `{ token: string max 2000 }`, verifies the MAC with `crypto.timingSafeEqual`, requires `viewer === requireUser().email` and age under 15 minutes, then appends that row (with `loggedBy` set to the viewer).
- `retryLogRow` is idempotent: read the last 30 rows of the log first and return `true` without appending when a row with the same saved-at, month, portion and action already exists.
- `appendLogRow` logs (`console.error` through the shared logger from 1B-6) the reason of each failed attempt.
- Clients send `{ token }`. Cap every remaining client string in the log schemas with `.max(200)`.
- Tests: forged row rejected, tampered token rejected, expired token rejected, other viewer rejected, replay does not duplicate, happy path.

### 1B-2 Signed freshness cookie (audit F2)

File: `src/lib/server/freshness.ts`. Cookie value = `${ts}.${base64url(HMAC-SHA256(AUTH_SECRET, ts + ":" + email))}`. `readWrittenAt(email)` verifies the MAC and rejects values older than 120 s or more than 5 s in the future. Pages pass the viewer's email. `/activity` and `/settings` use their own 15 s snapshot caches (same `createSnapshotCache`) invalidated by every write. Tests.

### 1B-3 Request integrity (audit F4)

File: `src/lib/server/http.ts` and every route. `assertJsonSameOrigin(request)` (content type must be `application/json`; if `Sec-Fetch-Site` is present it must be `same-origin`; if `Origin` is present its host must equal the request host) and a 32 KB body limit that also stops reading oversized streams. New HTTP statuses 415 and 413 (`validation` errors with a code or status override). Call both before the guard in every route handler. Tests in `tests/server/routes.test.ts` for each case.

### 1B-4 Security headers and CSP (audit F3)

Files: `next.config.ts`, `src/proxy.ts` (new), `src/app/not-found.tsx`, `src/app/robots.ts`, `public/.well-known/security.txt`.
- `next.config.ts`: `poweredByHeader: false`; headers on every path: `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), usb=(), browsing-topics=()`, `Strict-Transport-Security: max-age=63072000; includeSubDomains`, `X-Robots-Tag: noindex, nofollow`; `Cache-Control: private, no-store, max-age=0` on `/api/:path*`.
- `src/proxy.ts`: per-request nonce CSP: `default-src 'self'`; `script-src 'self' 'nonce-<n>' 'strict-dynamic'` (plus `'unsafe-eval'` only in development); `style-src 'self' 'nonce-<n>'` (development: `'unsafe-inline'`); `style-src-attr 'unsafe-inline'` (React inline `style` on the progress bar; or replace that bar with a `<progress>` element and drop the allowance); `img-src 'self' data: blob:`; `font-src 'self'`; `connect-src 'self'`; `manifest-src 'self'`; `object-src 'none'`; `base-uri 'self'`; `form-action 'self' https://accounts.google.com`; `frame-ancestors 'none'`; `upgrade-insecure-requests`. Pass the nonce on the request as `x-nonce`. Matcher excludes `/api`, `_next/static`, `_next/image`, icons and the manifest. Environment variable `CSP_REPORT_ONLY=1` switches the header name to `Content-Security-Policy-Report-Only` (documented emergency switch).
- `not-found.tsx` calls `await connection()` so it renders per request and receives the nonce. `robots.ts` disallows all. `security.txt` uses `Contact: https://github.com/vaibhavkannas/RentBook/security/advisories/new` and an `Expires` one year ahead.
- Verify by building and running `next start` with dummy environment values and a fake gateway (see how the earlier audit did it: a scratch copy outside the repo is fine): the headers are present on `/signin`, a protected page redirect, and `/api/*`; the browser console shows no CSP violations on `/signin`; every inline script carries the nonce. Add a test that unit-tests the CSP builder (pure function) including the report-only switch.

### 1B-5 Sessions and identity (audit F5, F12)

Files: `src/auth.ts`, `src/lib/server/auth-guard.ts`, `src/lib/server/env.ts`, tests.
- `session: { strategy: "jwt", maxAge: 7 days }`; a `jwt` callback stamps `token.issuedAt ??= Date.now()` and the `session` callback exposes it. `getViewer` rejects a session whose `issuedAt` is before `Date.parse(process.env.SESSION_NOT_BEFORE ?? "0")` (a "sign everyone out" switch: set it to now and redeploy); sessions without `issuedAt` count as issued at 0 only when `SESSION_NOT_BEFORE` is set.
- `readEnv` (and a new `assertAuthConfig()` used by `/api/health`) requires `AUTH_SECRET` of at least 32 characters, `AUTH_GOOGLE_ID` and `AUTH_GOOGLE_SECRET` present, with specific messages. Do not log values.
- `isAllowedEmail`: remove the default for `emailVerified`; the parameter is a required boolean; `getViewer` passes `true` explicitly. Update tests.
- Document `AUTH_URL` and `SESSION_NOT_BEFORE` in `.env.example` and `SETUP.md`.

- `src/lib/server/validators.ts`: `safeText(max, { allowNewlines })` zod helper (no control characters; trims) used for tenant names, portion names, phone and notes in `schemas.ts` and the domain validators; date range helper (years 2000 to 2100) applied to tenancy dates and `dateReceived`. Tests.
- `import "server-only"` at the top of `src/auth.ts`, every file in `src/lib/server`, and `src/lib/sheets/google-gateway.ts`; add the `server-only` package; confirm tests and build still work (the Vitest config may need an alias for `server-only`).
